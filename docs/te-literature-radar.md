# TE Literature Radar

`te-literature-radar` is the experimental lightweight thermoelectric literature monitor developed alongside the existing PaperEcho workflow. It searches Crossref, OpenAlex, arXiv, and optional RSS feeds; applies a hard TE relevance gate; asks Codex to judge novelty from supplied evidence; then generates deterministic A/B/C grades and a Markdown/HTML-email digest.

## Setup

Copy the example configuration:

```bash
cp te-literature-radar.config.example.json te-literature-radar.config.json
```

Edit `research_profile`, `target_authors`, `target_journals`, `rss_feeds`, and email settings as needed. SMTP passwords must stay in the configured environment variable or ignored secret file.

## Normal weekly/recurring run

A scheduler invokes one Skill run. The usual Codex Automation instruction is:

```text
Use $te-literature-radar with te-literature-radar.config.json in auto mode. Fetch new thermoelectric literature, assess novelty only from supplied evidence, validate the analysis, finalize the A/B/C digest, and send email if email is enabled.
```

The Skill does not hard-code weekly scheduling. Configure the desired weekday/time in Codex Automation (or another scheduler). `auto` starts from the last successful recurring run, overlaps 48 hours to reduce delayed-indexing misses, and deduplicates against state.

## Manual searches

Last 30 days without changing the recurring state:

```bash
python3 te-literature-radar/scripts/radar_cli.py fetch --config te-literature-radar.config.json --mode lookback --lookback-days 30
```

Explicit interval without changing recurring state:

```bash
python3 te-literature-radar/scripts/radar_cli.py fetch --config te-literature-radar.config.json --mode range --start-date 2026-01-01 --end-date 2026-06-30
```

Manual runs only move the recurring cursor if `--advance-auto-state` is explicitly requested.

## Outputs

Default output root: `te-literature-radar-output/`.

- `data/fetch-*.json`: normalized, gated candidates and deterministic base scores.
- `final/YYYY-MM-DD.json`: validated Codex analysis plus final scores/grades.
- `YYYY-MM-DD.md`: human-readable A/B/C digest.
- `state.json`: successful recurring seen IDs and last-success timestamp.

A/B entries contain purpose, innovation, how the problem was addressed, results, mechanism, significance, limitations, and a one-line radar judgment. C entries are compact browse items.

## Truthfulness rules

- Journal prestige cannot override a failed TE relevance gate.
- Codex cannot directly assign the final total or A/B/C grade.
- Numbers generated by Codex must already occur in the supplied title/abstract/metadata evidence; unsupported numbers fail validation.
- Title/abstract/metadata analysis must never be described as full-text review.
- Preprints are explicitly marked `Preprint — not peer reviewed` and face stricter grade thresholds.
- State advances only after the required final output (and email, when enabled) succeeds.
